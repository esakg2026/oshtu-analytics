# Аналитика ОшТУ

Дашборд загрузки аудиторного фонда Ошского технологического университета.
Разработчик: компания **ESA**. Владелец: **Эркебаев Самат Адылович**. Неофициальный сервис.

## Языки
Интерфейс на трёх языках: **русский, кыргызский, английский** (переключатель RU / KY / EN в шапке,
выбор запоминается, по умолчанию — язык телефона). Тексты — в `i18n.js`. Названия дисциплин, групп,
корпусов и ФИО приходят с сайта ОшТУ и не переводятся.

## Что показывает
- **Обзор:** аудиторий всего / используются / пустуют, средняя загрузка, пар в неделю, пиковая пара, число преподавателей, групп и дисциплин, автоматические выводы.
- **Типы аудиторий:** лекционные, практические, лабораторные, компьютерные (оценка по дисциплинам), смешанные, неиспользуемые.
- **Виды занятий:** лекции, практические, лабораторные.
- **Время:** тепловая карта «день × пара» (% занятых аудиторий), загрузка по дням и по парам.
- **Аудитории:** самые и наименее загруженные, неиспользуемые, полная таблица с поиском и сортировкой; карточка аудитории с недельной картой.
- **Корпуса:** загрузка каждого корпуса.
- **Преподаватели и группы:** рейтинг нагрузки и распределение.
- **Свободные аудитории:** на любой день, пару и неделю (кнопка «Сейчас»).
- **Накладки:** преподаватель в двух аудиториях одновременно, разные занятия в одной аудитории.
- Фильтры: корпус, неделя (обе / верхняя / нижняя).

## Как устроено
Supabase (проект family-finance): таблица `oshtu_room_index` — все аудитории всех корпусов;
`oshtu_private.collect_rooms()` по расписанию (pg_cron каждые 10 минут, по 30 аудиторий) забирает с portal.oshtu.kg
расписание «По аудитории» и обновляет каждую аудиторию раз в 6 часов. RPC `oshtu_room_dataset()` отдаёт всё одним запросом,
а расчёты (`engine.js`) идут прямо в браузере.

Как считается:
- **Загрузка** = занятые слоты / 36 слотов недели (6 дней × 6 пар); при «обе недели» — среднее.
- Поток нескольких групп в одной аудитории = **одна пара**.
- **Компьютерные классы** — оценка: ≥35% пар по IT-дисциплинам (информатика, программирование, БД…) и практические/лабораторные занятия. На сайте ОшТУ оснащение аудиторий не указано.
- В нагрузку преподавателей и групп входят только занятия с аудиторией в расписании.

## Наблюдение с камер (только для администратора)
Кнопка «📷 Камеры» открывает отдельное окно `cameras.html`. Вход без регистрации — одна учётная запись администратора;
пароль хранится в базе только как bcrypt-хеш, после 5 неверных попыток вход блокируется на 15 минут, сессия живёт 7 дней.
- **Камеры:** администратор указывает, какая камера в какой аудитории. Источники: камера этого компьютера (USB/встроенная),
  IP-камера с HTTPS-потоком MJPEG/снимком (нужен CORS) или видеофайл для проверки. RTSP-камеры — через OBS Virtual Camera или go2rtc.
- **Наблюдение:** TensorFlow.js COCO-SSD (lite_mobilenet_v2) прямо в браузере считает людей каждые 1,5 с; рядом показана
  пара по расписанию ОшТУ для этой аудитории и сравнение «план / факт». **Видео не отправляется и не сохраняется** —
  в базу уходит одна строка в минуту: время, аудитория, среднее/максимум людей, пара, предмет, группа, преподаватель.
- **Аналитика:** сколько пар по расписанию прошло под камерой, сколько состоялось (в среднем ≥ 3 человек), пустые пары,
  минуты с людьми вне расписания, среднее число людей по номерам пар и по аудиториям, список расхождений.
- Таблицы `oshtu_cameras`, `oshtu_cam_counts` (хранение 400 дней) доступны только через функции с токеном администратора.
